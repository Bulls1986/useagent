## 目标与背景
- 当前任务标题来自原始 Prompt 第一条非空行（`drafts.ts`），`learning/similarity.ts` 只以 `[a-z0-9]` 切词，纯中文标题没有匹配词，`titleSimilarity()` 变成 0。
- `skills/catalog.ts` 的自动预筛选也用英文/数字 Token 重合度；中文任务可能检索不到技能，影响端到端复用。
- 需要提升多语言（特别中文）、同义表达及真正相同业务目的的发现率，同时避免不同任务被错误合并。

## 现有规则与兼容原则
- 当前 `SIMILARITY_THRESHOLD = 0.5`，每个新接受的知识草稿需匹配至少 `MIN_SIMILAR_PRIOR_DRAFTS = 2` 条历史 accepted 草稿，才考虑 Skill Proposal。
- 第一版应保留人工双阶段审核及组织边界；原阈值作行为基线，新的相似度分数不可未经校准与旧值等同。
- 查询仅限当前 Org 的已接受记录；同名、同一 Session、模型提供商并不天然代表相似。

## 实施范围
- 建立中文/英文/混合文本基准样本：相同意图不同措辞、模板式“继续推进”、同标题不同目标、同项目不同仓库、否定意图与不同验收标准。
- 调整任务特征抽取：综合任务目标、最终结果、受控元数据、执行步骤特征与稳定的标题，避免只依赖 Prompt 第一行。
- 评估可控的多语言词法方案与可选语义检索/Embedding（优先复用现有 Knowledge/Context 基础设施），支持无向量服务时的有质量降级。
- 给聚类候选展示可解释的相似依据/来源 ID/版本或策略号；保留阈值与误匹配/漏匹配的测试指标。
- 同步审查 Skills Catalog 预填充和 `skill_activate` 前的中文匹配路径；不要求平台绕过 Agent 选择直接强制激活。

## 范围外
- 不新建全局向量基础设施，不默认引入额外模型厂商或大规模 LLM 每轮调用。
- 不开放跨 Org 聚类/自动共享；不改变技能本体存储或原生 Sandbox 下发（UA-BL-04）。
- 不用纯相似度代替最终成功证据或人工审核（UA-BL-10、UA-BL-12）。

## 风险与验收
- [ ] 中文同义任务（含不同首行提示）能按设定召回，纯中文不再恒为零。
- [ ] 仅“继续推进”“帮我修复”之类泛化标题不会把无关任务归成同一 SOP。
- [ ] 不同组织的数据和向量查询严格隔离；多用户权限及数据驻留不回归。
- [ ] 新旧评分/阈值有回归基线、误匹配控制和可解释依据。
- [ ] 中文新任务能发现已发布相关技能，未 Pin 时仍须由 Agent `skill_activate` 才采用。

> 待确认：是否复用现有 Embedding Provider、评估指标样本规模、各类回退策略的成本/延迟预算。
