# UA-BUG-03｜聊天 GitHub URL 错误提升为持久仓库，Run 失败后重复初始化阻塞会话

- **类别**：Run 生命周期 / Repository Admission / Native Runtime
- **优先级**：**P0**（影响会话可恢复性及后续消息交付）
- **状态**：Open investigation（2026-10-21 已有现场诊断；修复及 E2E 待验收）
- **首次记录**：2026-10-21
- **关联**：UA-BL-02（Native Session 连续性）、UA-BL-06（Cube Provider）、UA-BL-07（隔离/授权）

## 现象及已有证据

用户在普通对话里临时粘贴/提及 GitHub 仓库 URL（并未通过产品入口明确选择项目仓库）。该 URL 被系统提取并**提升为持久化 `repos`**；随后每次 Run 都执行 `prepareRepos()`，把此前的临时 URL 当成 Run 初始化资源。

2026-10-21 的源码与数据库排查显示：沙箱缺少 `git` 时，`git: command not found` 导致初始化失败；用户在同一 Session 输入新的消息仍会重复此前 Git clone；消息未真正交付 Codex，曾观察到 `prompt_delivered_at=NULL`。这不应简单归因于镜像缺 git；**错误持久化和失败后重试阻塞是独立的应用层缺陷**。本记录不表示最新 main 已完成复现或修复。

## 已确定的产品与架构语义

1. **明确选择的项目仓库**：只允许经用户/工作区/项目明确配置的仓库进入 Session/项目的持久化 `repos`，供 Sandbox Workspace 初始化使用；对地址、权限和绑定来源留有可审计证据。
2. **聊天中临时出现的 URL 或 Git 命令**：保留为普通用户指令交给当前原生 Agent Runtime 处理；**不得**通过隐式 URL 检测、意图猜测或 Run 文本解析写入持久仓库列表。Agent 自主 clone 的文件可存在当前沙箱工作区，但不得自动转化为后续 Run 的“强制预检”。
3. **Run 初始化失败**：必须保留失败阶段与错误原因并终止本次失败步骤，不得永久污染 Session。之后新消息应能够建立下一次正常执行/继续 Runtime，而不是重复触发非显式仓库初始化；确有明确绑定的必需仓库时，应明确标识资源准备失败，提供重试/解绑/修复入口，避免静默吞掉新消息。
4. **沙箱工具环境**：镜像是否预装 `git` 属模板构建/环境校验问题，需单独修复和验证；不可借修镜像掩盖自动持久化缺陷。

## 预期实施范围

- 追踪从 Chat 请求/消息 URL 抽取、Session/Thread `repos` 变更、Run 初始化、`prepareRepos()` 到 Agent 输入交付的完整调用链，明确哪个阶段将普通消息提升为持久配置。
- 引入明确的 **Repository Admission** 规则：持久配置必须来自结构化显式选择/操作；旧数据升级或污染处理应有安全迁移/纠正策略，避免把历史意外仓库继续带入新 Run。
- 将初始化失败状态与 Session 可用状态解耦；记录故障、允许恢复/后续消息交付；区分必需资源失败与临时命令失败，限制无意义的重试和重复克隆。
- 为 Codex、OpenCode、Claude Code 原生 Runtime 均建立行为一致性验证；不得重写 Agent 内部 Git/tool 执行循环。
- 保留原有明确绑定项目仓库时的初始化能力与线程隔离/权限校验。

## 不做的事

- 不以“禁用所有 Git clone”替代修复。
- 不把普通聊天 URL、Shell 命令默认转化为配置；不以模型推断作为持久化授权。
- 本项只登记/调查，未经另行明确启动，不顺带修改沙箱镜像或仓库根 `README.md`。

## 验收清单

- [ ] 普通文本提及 GitHub URL、引用网页及要求 Agent 临时 clone：数据库持久 `repos` **不变**；任务可由 Runtime 自行执行。
- [ ] 从项目/工作区 UI 显式选定仓库：按原预期进行一次所需初始化并可在后续 Run 使用；解绑后不继续预检。
- [ ] Sandbox 中缺少 `git` / clone 403 / DNS 失败 / 超时：报错包含阶段与原因；不会无限重复历史非显式初始化。
- [ ] 失败 Run 后同 Session 继续发新消息：新消息到达 Runtime，有交付确认（如 `prompt_delivered_at`），不会重新消费上一条失败 clone。
- [ ] 修复前受污染的历史 Session：有数据识别、纠正和回归方案，不丢失合法的明确仓库绑定。
- [ ] Codex / OpenCode / Claude Code、Cube/Local 支持的真实链路回归；正常项目仓库准备、取消、断连重连、会话恢复与 Streaming 不退化。
- [ ] 通过自动化单测/集成测试和可复现的端到端日志；附最终 commit、测试和部署证据后才能标记 Done。

## 待调查和决策

- 实际持久化写入函数/表及其触发条件；Session、Thread、Run 上 `repos` 的唯一权威数据源。
- 显式仓库绑定变更的产品交互与授权/审计模型。
- 有必需仓库初始化失败时的 Retry/Unbind/Continue UX 与历史污染数据修复策略。
